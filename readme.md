# Student Success Assistant

An applied-AI take-home in three parts:

1. **Part 1, dropout prediction.** Which students are likely to quit, predicted early enough to help (day 14 after signup).
2. **Part 2, LLM grader.** Read a student's own explanation of a lesson and return structured JSON: a verdict
   (`understood` / `partial` / `wrong`), which key points they got right or missed, feedback and a hint.
3. **Part 3, research memo.** Which LLM to run for 50,000 students a month, and when a small ML model beats an LLM.

A Streamlit app (`app.py`) demonstrates all of it live, including a raw JSON output window.

> **How this was built:** the code, notebooks and documents were generated by an AI coding assistant, not written
> by hand. See [How this was built](#how-this-was-built-ai-assistance-disclosure).

### `src/`: Part 1, dropout prediction

**`dropout.ipynb`: step 1, cleaning.**
It profiles every file, fixes each problem and logs the reason:
- **Removed:** 3 impossible scores (`999`), and 18 duplicate attempts hidden behind unique IDs.
- **Filled:** 95 missing quiz times, with the median for that lesson plus a flag column.
- **Kept, with zero activity:** student S065, who made no attempts.
- **Labelled `"unknown"`:** missing age group and device. A missing device predicts dropout (44% against 24%).
- **Kept out of the model:** `refund_requested`, because it leaks the answer.

*Run:* Run All.

**`features.ipynb`: step 2, features.**
- **Shows the timing problem:** in their first two weeks, dropouts take *more* quizzes, not fewer.
- **`build_features()`** makes one row per student using only the first `WINDOW_DAYS = 14` days: counts, scores,
  time spent, days to the first attempt, days active, days since the last attempt, and the profile columns.

*Run:* Run All. To predict at a different point in time, change `WINDOW_DAYS` and re-run steps 2–4.

**`model.py`: step 3, training.**
It cross-validates six experiments (5 folds × 5 repeats = 25 test folds):

| Experiment | What it is |
|---|---|
| `majority` | Always predicts the base rate |
| `one_rule` | A decision stump on `mean_score` |
| `logreg` | Logistic regression, the main model |
| `gboost` | Gradient boosting |
| `logreg_no_country` | The fairness check |
| `logreg_leaky` | Whole-course data + refund, to show the leak |

Missing values are filled and features scaled **inside** each fold, so nothing leaks from the test students. It
saves every student's out-of-fold risk, and fits the final model (logistic regression without country).
*Run:* `python src/model.py` (about 10 s; seeded, so the results repeat exactly). The feature lists are at the top
of the file.

**`evaluate.ipynb`: step 4, evaluation.**
It reads the saved predictions and retrains nothing. It covers:
- why recall matters most, and why accuracy misleads;
- every experiment as mean ± std;
- the leak in one chart;
- precision–recall curves;
- **the threshold choice** (0.35 catches 81% of dropouts), and what it means for tutors;
- the fairness check;
- the model's coefficients.

*Run:* Run All. To try another threshold, change `MY_THRESHOLD`.

### `src/`: Part 2, the LLM grader

**`prompts.py`: what we ask and what we accept.**
- `load_lessons()`: reads the rubric.
- `build_messages()`: the 3 prompt versions (`v1` naive, `v2` careful rules, `rag` = `v2` + graded examples).
- `Grade`: the JSON schema the LLM must reply with. For each key point it credits, it gives the student's exact words
  as evidence (`credited`).
- `GradeResult`: the strict output schema (`explanation_id`, `lesson_id`, `verdict`, `got_right`, `missed`,
  `evidence`, `hint`, `feedback`, `misconception`, `instruction_in_text`).
- `parse_reply()`, `quote_in_text()` and `to_result()`, which connect the two, including the **evidence check**:
  credit whose quote isn't in the student's answer is rejected.

> **The evidence check was added after the evaluation.** The saved results in `data/llm/`, and every number in the
> notebook and docs, come from the grader *before* it. The check is tested offline (`tests/test_evidence_check.py`)
> but not yet evaluated on the full set; a first run hit Groq's free daily token limit. See `docs/grader.md` for its
> status, how to run it, and the fallbacks if the quota runs out.

**`retriever.py`: finding examples (the "R" in RAG).** It picks 3 teacher-graded answers from the same lesson, one
per verdict, by text similarity. It never shows the answer being graded, or anything more than 85% similar to it.

**`grader.py`: the pipeline and the command line.** A 4-step LangGraph pipeline: **guard** (an injection check) →
**retrieve** → **grade** (the LLM, or a saved reply) → **validate** (schema check, retried once). Models, keys and
limits are set at the top in `MODELS` and `PROVIDERS`.

```bash
python src/grader.py eval                    # Qwen x prompts v1, v2, rag on 60 labels + 4 injection attempts
python src/grader.py compare                 # 10 random labels x Qwen, Gemini, Gemma (rag prompt)
python src/grader.py at-risk                 # 5 at-risk students -> at_risk_feedback.json
python src/grader.py one E0508               # grade one explanation, print its JSON
python src/grader.py one E0508 --model gemma --version v2
python src/grader.py eval --mock             # any task with a fake offline model (no keys)
```

In Python: `Grader().run(text, lesson_id, model, version)["result"]` returns the `GradeResult` as a dict.

**`evaluate_grader.ipynb`: evaluating the grader.** It covers:
- valid output and retries;
- agreement with the teacher per prompt, with 95% intervals;
- what each prompt fixed and broke, with a sign test;
- confusion matrices;
- hedging and confident-nonsense failure modes;
- Hinglish;
- prompt injection;
- a check that retrieval never leaks the answer;
- every miss;
- whether `got_right` can be trusted;
- the 3-model comparison;
- cost inputs;
- the 5 at-risk results, validated against `GradeResult`;
- written findings.

*Run:* Run All.

### `src/`: Part 3 bonus

**`baseline_text_clf.py`.** A TF-IDF + logistic regression classifier trained on the 60 labels and compared with the
LLM. It scores **80%** with leave-one-out, which is misleading because near-copies of each answer sit in training,
and only **38%** when near-copies are held out together (chance is 33%).
*Run:* `python src/baseline_text_clf.py`.

## 4. Results at a glance

| | Result |
|---|---|
| Data problems | 3 impossible scores; 18 hidden duplicates; 95 missing times; 1 student with no attempts; missing device linked to 44% dropout; **`refund_requested` leaks the answer** |
| Dropout model (day 14) | Logistic regression, ROC-AUC 0.76 (average over 25 test folds). At threshold 0.35 it catches 81% of dropouts, with 37% of flags real |
| With the leak | ROC-AUC 0.99: looks great, but impossible in production |
| Grader (Qwen, 60 labels) | 86.7% (`v1`) → 96.7% (`v2`) → **98.3% (`rag`)** agreement with the teacher; no wrong answer passed; all 4 injection attempts failed |
| Model comparison (10 labels) | Qwen, Gemini and Gemma all 10/10; median 8.5 s / 6.7 s / 17.4 s per answer |
| Bonus text classifier | 80% looks good, but only **38%** when near-copies are held out together |
| Recommendation | Qwen3.8-27B + `rag`, about $87/month for 72,500 answers. Pilot on Groq with Zero Data Retention, then host in India; Gemma as the fallback |
| Evidence check (added after the evaluation) | Tested offline. On the 55 answers a first live run completed, all 96 quotes were genuine; the full run is pending (Groq's daily limit) |

**Limits:**
- **The evaluation is small:** 60 labels, only 3 of them Hinglish, and no Tamil or Kannada.
- **The model comparison** uses just 10 answers.
- **The dropout threshold** was chosen on the same predictions it's reported on.

## 5. Assumptions

- **Prediction moment:** day 14 after signup. Features only use data available by then.
- **Dropout:** whatever `outcome.csv` says. There are no dropout dates, and 51 of the 125 dropouts went quiet before day 14.
- **Monthly volume** for costing: 50,000 students × 1.45 explanations each (the ratio in the data) = 72,500 gradings.
- **Prices** were checked on 22–23 Oct 2026; the sources are cited in the memo.
